# 中心知识维护

知识正文属于中心运行期私有数据，不随源码、镜像或管理前端发布。测试只使用合成数据。

## 开关与权限

KNOWLEDGE_ENABLED 默认 false，用于控制后续在线检索和采集能力。管理员可在关闭状态下预先维护集合、站点、来源与草稿；保存配置不会发起网络采集。

维护 API 位于 /admin/api/knowledge，使用现有后台会话、管理员角色和写操作 CSRF。响应禁止缓存。该入口不接受 MP 自报的 GitHub 用户名或实例 UID 代替后台认证。

现有后台账号、角色和会话配置见 [管理后台](ADMIN.md)。

## 基础维护接口

| 路径 | 方法 | 作用 |
| --- | --- | --- |
| /status | GET | 在线功能是否启用 |
| /collections | GET / POST | 分页查看、新建集合 |
| /collections/{id} | PUT | 按版本更新显示信息和启停状态 |
| /sites | GET / POST | 分页查看、新建站点与别名 |
| /sites/{id} | PUT | 按版本更新站点与别名 |
| /sources | GET / POST | 分页查看、新建明确来源配置 |
| /sources/{id} | PUT | 按版本更新来源 |
| /documents | GET / POST | 查看摘要、新建手工知识草稿 |
| /documents/{id} | GET | 读取最新修订，revision 可指定历史修订号 |
| /documents/{id}/revisions | POST | 按文档版本追加新草稿 |
| /documents/{id}/publish | POST | 按当前文档版本批准明确修订，返回索引任务 |
| /documents/{id}/withdraw | POST | 按版本清除发布指针、保留历史并请求重建 |
| /clients | GET / POST | 超级管理员查看客户端、签发一次性展示的独立令牌 |
| /clients/{id} | GET / PUT | 超级管理员查看、按版本维护状态、期限及完整集合授权 |
| /clients/{id}/rotate | POST | 超级管理员按版本轮换令牌，旧令牌对后续请求失效 |
| /jobs | GET | 分页查看任务真实状态及计数 |
| /jobs/index | POST | 手动排队重建索引，空 JSON 对象为唯一请求体 |
| /jobs/{id}/cancel | POST | 按任务版本取消或请求取消 |
| /imports/upload | POST | 鉴权后流式上传未压缩 JSONL，query 明确 source_id、source_version |
| /imports | GET | 分页查看批次元数据 |
| /imports/{id} | GET | 查看批次、明确映射和真实任务 |
| /imports/{id}/preflight | POST | 按版本排队预检字段、身份、来源与差异 |
| /imports/{id}/rows | GET | 分页查看计划元数据或实际行回执 |
| /imports/{id}/rows/{line} | GET | 查看单行旧版与候选；被阻止行不回显候选正文 |
| /imports/{id}/apply | POST | 明确确认后排队导入待审修订，不批准发布 |
| /imports/{id}/discard | POST | 按版本丢弃非活动暂存，保留实际修订和回执 |

列表参数 page 从 1 开始，size 最大 100，q 为名称或标题包含查询。来源可用 collection_id 筛选，文档可用 source_id 筛选。

更新使用 expected_version，与读取结果的 version 一致时才能成功。冲突返回 HTTP 409；请重新读取再编辑，不能重复提交旧表单。集合稳定标识不能修改；已有来源的集合产品和领域、已有文档的来源身份和归属不能被普通编辑改写。

## 独立客户端与授权

只有超级管理员可以管理客户端及集合授权；普通管理员不能通过知识维护接口给自己增加读取范围。签发与轮换接口也要求现有后台 Cookie 和 CSRF；知识令牌不具有后台管理权限。

中心为每个客户端生成独立的 256 位随机令牌，带 mpk_ 前缀。数据库只保存当前令牌的 SHA-256 摘要；原值只在成功签发或轮换响应的 token 字段中出现一次，不进入列表、回读、普通更新或审计。请通过受保护的部署配置保存令牌，不要写入代码、URL 或公开日志。数据库备份包含敏感授权元数据，也应限制访问。

创建与更新字段为 name、enabled、expires_at、collection_ids；更新另带 expected_version。expires_at 必须包含时区，null 表示不设期限。collection_ids 为明确集合 ID 列表，空列表没有读取权限，不表示全部集合。新增授权只能选择已启用集合。已有停用集合的授权可保留用于管理，但认证时不会生效；以后重新启用集合会恢复这些保留授权，需要永久撤回时应同时从客户端范围移除。

客户端更新和令牌轮换共用 version，任何冲突都返回 409，避免旧表单覆盖新的范围或密钥。轮换请求仅接受 expected_version。令牌明文不能找回；如果成功响应丢失，请先重新读取当前版本，再明确发起一次新轮换。不要盲目重试旧请求，也不要以为再次提交会返回上次的原值。

供后续检索路由复用的 Bearer 认证依赖每次读取当前客户端状态、有效期与集合开关；停用客户端、到期、替换令牌和撤回授权会影响后续请求，不使用共享权限缓存延迟撤回。已开始的请求不承诺中途取消。自报实例 UID、GitHub 用户名、推送令牌或后台 Cookie 都不能替代独立知识令牌。

在线开关关闭时认证返回 503；无效或失效凭据返回 401；有效客户端没有可用集合时返回 403。后续检索工具应区分这些状态和“没有匹配知识”，不能据此编造规则。当前只提供后台维护接口和可复用认证合同，尚未注册公共检索或认证探针路由。

## 批准发布与独立索引

发布请求必须同时包含 expected_version 和明确的 revision。追加草稿不会自动发布，也不会改变原有发布版；发布前应查看目标修订。来源、集合及所属站点均须启用，才能批准发布。publish 响应的 index_pending 表示仍需构建；job.status 为 queued 不能当作已可检索。后台 status 的 generation 表示当前知识事实代次，active_generation 表示已激活快照代次，has_snapshot 只描述 SQL 是否存在快照指针，不代替文件可用性检查。

withdraw 请求包含 expected_version。撤回会在同一事务清除 SQL 发布指针并排队重建。原文历史保留，不能通过回退旧快照恢复读取权限；检索必须重新核对当前 SQL 指针和授权。集合、站点或来源的启停同样会请求重建；重新启用只带回仍被批准发布的修订。

索引任务持久化在数据库中，相同活动索引请求合并。构建期间有新的发布、撤回或开关变化时，完成者不会激活过时代次，而是补排下一任务。任务列表区分 queued、running、succeeded、failed、cancelled；outcome 为 activated 才表示此次完成了切换，superseded 表示构建期间事实改变，后继任务仍需执行。

worker 不在 Uvicorn 生命周期中运行。配置一个仓库之外的专用持久化数据卷，目录仅属主可访问，给 API 与 worker 挂载同一卷和 SQL 数据库，并在两个进程中显式设置：

    KNOWLEDGE_ENABLED=true
    KNOWLEDGE_DATA_DIR=/config/knowledge

独立运行：

    python -m app.services.knowledge.worker

本地或运维单次执行：

    python -m app.services.knowledge.worker --once

同一 Server 镜像可以通过覆盖 command 运行 worker，默认 Web 启动命令保持不变。首次必须运行包含知识表的数据库结构初始化；worker 自己也会调用现有结构初始化。私有目录不能位于源码、Git 仓库或共享临时目录中；现有目录权限过宽会明确报错，不会自动改动已有共享目录权限。索引为 0400 不可变 SQLite FTS5 文件，目录为 0700。FTS5 不可用会返回固定错误码并受控重试，不会替换为全库扫描或伪成功。

执行器使用 60 秒租约、约 20 秒心跳和单次 10 分钟构建期限；失败最多尝试三次，按 15、30 秒退避。旧租约不能续命或切换索引。等待中的任务可立即取消，运行中的取消由心跳及激活前检查确认；进程强制终止后由租约到期恢复。SIGTERM 停止继续认领并等待当前有界构建。worker 日志、任务错误和审计只记录标识、计数与白名单错误码；数据库引擎即使开启 DEBUG 也隐藏绑定参数。

若激活事务失去提交回执，可能已经提交，因此执行器保留完整快照，再按数据库事实恢复，不能因为网络异常删除已上线文件。旧快照与不确定提交遗留文件暂保留在私有卷中；读端及快照清理合同接通前，请勿把该基础阶段作为长期频繁重建的生产配置。公开检索和网络来源执行尚在后续阶段。

可选 PostgreSQL 合同测试通过 KNOWLEDGE_TEST_DATABASE_URL 显式指定本机 knowledge_test 专用数据库。每个案例使用随机 schema 并在结束后删除，拒绝使用其他数据库名；未提供配置时明确跳过，不把方言编译当作数据库集成测试。

## JSONL 预检与明确导入

先建立 connector 为 jsonl 的来源，明确集合、产品与可选站点。上传使用原始 application/x-ndjson 正文，query 参数为 source_id 和当前 source_version，仍需 Cookie 和 X-CSRF-Token。不能上传 ZIP 或其他压缩体，不能指定文件系统路径。Nginx 专用入口最大 64 MiB，关闭请求缓冲并保留认证头；API 在认证后累计检查实际字节，不依赖 Content-Length。

单文件最多 64 MiB，单行最多 1 MiB，最多 50000 行。暂存准入为 512 MiB、最多四个未完成批次；不足时应完成或丢弃旧批次。上传期限五分钟，成功后暂存有效期 24 小时。独立 worker 或后续上传操作会清理到期批次；没有执行器运行时不承诺到点立即删除。有效运行租约持有的文件不会被到期清理误删。导入任务串行处理以控制暂存与事务资源，索引任务仍可由其他 worker 运行。

建议每行至少提供 external_id、title、content，可选 source_url 及明确版本元数据。external_id 是来源内稳定身份。inline-bot 式记录可使用以下预检配置；同一 source_id 可能对应多个文本块，直接拿它作为唯一身份会形成可见重复，不能默默覆盖：

    {
      "expected_version": 2,
      "expected_source_version": 1,
      "identity_fields": ["source_id", "title"],
      "title_field": "title",
      "content_field": "content",
      "url_field": "url",
      "origin_field": "source_id",
      "origin_values": ["explicit-source-to-import"],
      "metadata_mode": "fixed",
      "metadata": {"version_scope": "unknown"}
    }

字段只按顶层键读取，不执行脚本或 JSONPath。复合身份生成稳定摘要；标题等身份字段变化会成为新身份，因此应结合真实导出结构选择长期稳定字段。origin_values 只筛选外部记录，不决定中心权限；中心归属由后台来源绑定决定。筛掉的记录有明确计数与回执。若来源混杂，应分组选择到合适集合，不能把整包猜成同一产品。

metadata 必须明确 version_scope 为 unknown、all 或 range。fixed 模式不接受记录与明确范围矛盾；record 模式保留记录自带的标准元数据，并用批次值补充缺失项。产品、站点和中心归属仍不得越过后台绑定。未知时间保留 null。出处可保留 HTTPS 章节或行号片段，但不能携带认证参数；实际抓取地址仍禁止片段。

预检是独立 import 任务，返回 202 只表示排队。完成后查看 rows 列表与单行详情；列表不含正文，单行可对照所审阅基础修订与候选。重复身份、无效数据或疑似秘密形成阻止行；疑似秘密仅是启发式检查，不保证发现所有秘密，维护者仍应审阅。内容指令作为不执行的数据标记警告。被阻止行不回显候选正文。

apply 请求包含当前 expected_version、acknowledge_warnings，以及可选 skip_lines、append_lines。阻止行必须明确跳过或修正文件，人工修改冲突需逐行选择追加或跳过，重复 / 矛盾的决定会拒绝；不会静默跳过坏数据。每种行选择最多 1000 条，大范围问题应修正或拆分文件。

执行时再次核对计划摘要、来源版本与所审阅文档版本。所选写入、无正文行回执和任务终态在同一 30 秒有界事务提交；故障回滚，重试不会重复追加。状态为 review，原发布指针保持原样。已导入批次的原文件和计划随后清理，行回执仍能关联实际修订及旧版差异。人工保护以实际写入回执判断，不因为一次 unchanged 确认就把人工修订变成可自动覆盖的内容。

取消、丢弃、过期和提交回执丢失分别有明确状态；已经提交的导入不会因之后取消而撤销。若状态或计划过时，重新读取并预检，不要重复提交旧确认。附件不会自动导入，正式知识仍需单独审核和发布。

## 来源与正文

集合区分 mp、pt 领域，可自定义集合标识和显示名称，产品分支应使用独立集合。站点域名、名称和别名统一做歧义检查；同一规范化称呼不能指向两个站点。

来源类型包括手工文本、JSONL 导入、GitHub、HTTP 文档和 NexusPHP。此处仅维护其明确参数；只有手工来源可以通过文档接口直接新增草稿。网络来源保存期间不执行抓取。

来源字段不能填写 Cookie、密码或认证 URL。当前基础接口不接受秘密字段，验证错误也不会回显误填的请求输入。涉及采集凭据时，应使用独立的受控凭据维护能力，不能塞进 URL、路径或选择器。

正文保留 Markdown 空白，修改只追加新修订。新修订默认是 draft，不会自动发布，也不会改变已有发布指针。列表与操作审计不包含正文。

适用版本必须明确选择 unknown、all 或 range；范围边界使用稳定版本号。未知采集时间保持 null，中心录入时间不能代替真实采集时间。知识服务不可用或尚未发布时，调用方不能把这种状态解释为规则不存在。
