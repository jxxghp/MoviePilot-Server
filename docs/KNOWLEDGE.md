# 中心知识维护

知识正文属于中心运行期私有数据，不随源码、镜像或管理前端发布。仓库测试只使用合成数据。

## 开关与权限

中心知识默认关闭。部署配置 `KNOWLEDGE_ENABLED` 可作为默认值；超级管理员还可在“权限与功能 → 中心知识”中设置在线总开关。后台显式开关覆盖部署默认，关闭后 Agent 公共检索、知识采集和索引任务暂停。启用后，所有 MoviePilot Agent 均可读取启用集合中已发布的知识，不需要用户登记客户端、填写 URL 或令牌；后台采集凭据不会返回给调用方。`KNOWLEDGE_TRUSTED_PROXY_ADDRESSES` 只应配置会覆盖写入 `X-Real-IP` 的可信反向代理 IP 或网段，默认信任回环和私有容器网络。关闭时仍可预先维护集合、站点、来源与草稿；保存来源配置不会发起网络采集。

维护 API 位于 /admin/api/knowledge，使用现有后台会话、管理员角色和写操作 CSRF。响应禁止缓存。该入口不接受 MP 自报的 GitHub 用户名或实例 UID 代替后台认证。

现有后台账号、角色和会话配置见 [管理后台](ADMIN.md)。

## 后台操作

从现有后台导航进入“知识中心”（/admin/knowledge）。来源、站点、集合、知识和任务使用同一入口；在线开关关闭时仍可预先维护，页面会明确提示检索和执行器暂停。

先维护集合和可选站点，再新建来源。选择器支持名称搜索、分页和按 ID 回读选中项，不限于首屏记录。来源可按集合、站点筛选；手工新增知识只允许选择手工来源。站点别名供检索时解析，不能与其他站点的名称或域名产生歧义。

来源的“凭据”窗口只展示配置状态，同时列出完整目标和额外批准路径；超级管理员可以填入新值、清除或用部署当前密钥重新加密。任何角色都不能回读旧值；输入在提交、关闭和角色变化时清空，不保存到浏览器持久化存储。绑定凭据或已有文档的身份字段会锁定，服务器保存时仍重新检查。

在“采集”窗口明确版本范围；有未保存修改时须先保存，再触发采集。“立即采集”只返回排队任务，可跳转任务详情查看真实状态、索引文档 / 分块统计、逐页回执、警告和受保护的上游候选。任务页面可请求重建索引或取消任务；运行中取消需等待执行器确认，不会回滚已提交结果。

“知识”区可读取历史修订、将所见内容编辑为新草稿、明确发布所见修订或撤回当前发布版。正文按安全原文展示，不执行其中的 HTML、脚本或指令。上游候选可与当前人工正文对照，确认警告后追加为待审，或明确忽略；追加候选不会自动发布。

编辑遇到并发版本变化时保留输入，按字段对照最新版；双方均修改的字段需明确选择，采用对照结果后仍须再次保存。发布、撤回或候选动作冲突则重新读取并审阅，不自动套用新版本重试。页面状态与凭据只在当前内存中，不写入 localStorage 或 sessionStorage；任务轮询在页面不可见、在线服务关闭或组件卸载时停止。

### 文件导入

“导入”区接受未压缩的 .jsonl / .ndjson 原始文件，单文件最大 64 MiB；不解压 ZIP，也不在浏览器解析整个包。先选择 JSONL 来源，上传只进入私有暂存；随后明确字段映射、外部来源允许值、产品和版本范围，再排队预检。包中的 source_id 是外部来源标识，必须显式映射，不能用它获得中心集合授权。未知采集时间和适用版本保留未知。

预检按页展示动作与警告，正文需逐行打开对照。阻止行不回显原文件候选正文；须明确跳过。人工修订冲突须明确选择追加为待审或跳过，并确认全部警告。决定可跨页保留，但只属于当前窗口和当前计划；计划变化或重新读取审阅会清空决定。单次跳过、追加各最多 1000 条，超过时应调整文件分批处理，不自动截断。

“确认计划并导入待审”仍需输入确认词，任务完成后可读实际逐行回执。新内容不自动发布，也不覆盖原发布指针。丢弃暂存会清除私有上传文件，已导入的历史修订与回执仍保留。上传或提交结果未确认时，先返回列表核对实际批次和任务，页面不会自动重发。

### 客户端与检索测试

超级管理员可进入“接入授权”，维护客户端状态、期限和完整集合范围。空范围没有读取权限；选择器只允许新增启用集合，已有停用集合授权会保留并明确标注，永久撤销需移除。授权的并发变化按名称对照，采用对照结果后仍须再次保存。

签发或轮换成功后，令牌只在独立窗口中显示一次，默认遮盖；关闭、切换分区或身份变化时清空。只有明确点击复制才写入剪贴板。令牌响应丢失时先核对当前版本，再明确重新轮换，不能找回旧值或自动重放。

“检索测试”仍可用独立知识令牌调用 `/knowledge/v1/search` 和 `/read` 检查指定集合授权；Agent 则固定调用无需配置的 `/knowledge/v1/agent/search` 和 `/agent/read`。Agent 公共接口只返回启用集合中已发布的资料，并按连接地址限流；短期引用也绑定该地址。

## 独立客户端与授权

只有超级管理员可以管理客户端及集合授权；普通管理员不能通过知识维护接口给自己增加读取范围。签发与轮换接口也要求现有后台 Cookie 和 CSRF；知识令牌不具有后台管理权限。

中心为每个客户端生成独立的 256 位随机令牌，带 mpk_ 前缀。数据库只保存当前令牌的 SHA-256 摘要；原值只在成功签发或轮换响应的 token 字段中出现一次，不进入列表、回读、普通更新或审计。请通过受保护的部署配置保存令牌，不要写入代码、URL 或公开日志。数据库备份包含敏感授权元数据，也应限制访问。

创建与更新字段为 name、enabled、expires_at、collection_ids；更新另带 expected_version。expires_at 必须包含时区，null 表示不设期限。collection_ids 为明确集合 ID 列表，空列表没有读取权限，不表示全部集合。新增授权只能选择已启用集合。已有停用集合的授权可保留用于管理，但认证时不会生效；以后重新启用集合会恢复这些保留授权，需要永久撤回时应同时从客户端范围移除。

客户端更新和令牌轮换共用 version，任何冲突都返回 409，避免旧表单覆盖新的范围或密钥。轮换请求仅接受 expected_version。令牌明文不能找回；如果成功响应丢失，请先重新读取当前版本，再明确发起一次新轮换。不要盲目重试旧请求，也不要以为再次提交会返回上次的原值。

Bearer 认证每次读取当前客户端状态、有效期与集合开关；停用客户端、到期、替换令牌和撤回授权会影响后续请求，不使用共享权限缓存延迟撤回。已开始的请求不承诺中途取消。自报实例 UID、GitHub 用户名、推送令牌或后台 Cookie 都不能替代独立知识令牌。

在线开关关闭时认证返回 503；无效或失效凭据返回 401；有效客户端没有可用集合时返回 403。检索工具须区分这些状态和“没有匹配知识”，不能据此编造规则。认证探针只存在于测试应用，产品不注册。

## 只读检索协议

受限客户端入口为 POST `/knowledge/v1/search` 和 POST `/knowledge/v1/read`，要求 Authorization: Bearer 独立知识令牌。MoviePilot Agent 使用 POST `/knowledge/v1/agent/search` 和 POST `/knowledge/v1/agent/read`，不要求客户端账号或令牌，只能读取启用集合中的已发布资料。请求和响应均使用 protocol_version: 1。不接受后台 Cookie、自报 UID、任意抓取 URL、SQL、脚本或全集导出。API 和专用 Nginx 路径均禁止缓存。

搜索请求示例（MP 查询可省略站点；PT 泛查包含通用知识与明确标注的站点示例）：

    {
      "protocol_version": 1,
      "query": "订阅未命中时如何检查过滤规则",
      "product": "moviepilot",
      "product_version": "3.2.5",
      "domain": "mp",
      "purpose": "troubleshooting",
      "limit": 5
    }

query 为最长 300 字符的独立问题，不发送整个聊天记录或原始日志；疑似凭据会拒绝，但启发式检查不能代替客户端脱敏。product 为宿主确定的产品标识；product_version 为宿主当前稳定版本，未知或开发版本传 null，不能让模型猜版本。domain 可选 mp / pt；site 可用后台维护的站点名称、域名或别名。明确站点时可同时返回通用材料。PT 未知或未指定站点时也会检索带站点名称的参考示例，并附 `pt_site_examples_only`；调用方须把示例当例子，不能自动推广为目标站点已核验的规则。未知 PT 站点还会附 `unknown_or_unavailable_site`，不暴露站点清单。

purpose 可选 usage、troubleshooting、development，默认 usage。常规问题优先指南，排除明确测试路径；development 可返回实现与测试，但测试标记 test_reference_only，不能直接当成使用规则。分类依据来源路径，不是语义真实性保证。中文双字、英文配置名和少量受控同义词用于词法检索，输入永远是字面查询；当前没有向量检索或中心聊天模型，命中也不保证足以回答问题。

响应包含 request_id、corpus_revision、status、evidence、notices、retention: ephemeral、content_trust: reference_only。每篇文档最多一个片段，最多五篇，每段最多 1600 字符，单次搜索正文总量最多 6000 字符。各证据含标题、出处、源修订、产品 / 站点（站点级资料带 `site_name`）、版本范围、真实采集时间和时效说明；未知范围或时间保持未知，不能拿中心入库时间代替。产品、版本、站点和内容类型先于有限候选截断过滤；返回正文前再用 SQL 当前发布指针和启停状态核对。

| 结果 | 含义与调用方处理 |
| --- | --- |
| 200 matched | 有当前范围的证据，结合 notices 判断是否足够回答 |
| 200 no_match | 当前可用索引内没有词法匹配，不代表规则或功能不存在 |
| 200 not_applicable | 范围不可用，或仅找到明确过期 / 版本不适用材料；不含其正文 |
| 200 conflicting | 同身份和范围的条目出现文本差异，提示核对出处；不是语义冲突判决 |
| 401 / 403 | 凭据失效或没有授权，不能静默换身份或扩大范围 |
| 410 | 引用过期、归属不符、发布版变化或权限失效，应重新搜索 |
| 413 / 415 / 422 | 请求过大、编码不支持或字段无效，先修正请求 |
| 429 | 调用限额，遵守 Retry-After，不能无限重试 |
| 503 | 未启用、SQL / Redis / 快照不可用、索引未就绪、忙碌或超时；不冒充没有知识 |

资料新旧代次不一致时，若还能找到经过 SQL 复核的证据会附 index_updating；找不到时返回 503 knowledge_index_updating，等待执行器重建后再试。旧格式快照也明确返回 503；升级后通过后台 jobs/index 手动请求重建，并运行 worker，不在在线请求中重建。

每项证据带短期随机 evidence_id，补读只接受 {"protocol_version":1,"evidence_id":"搜索返回值"}。受限客户端引用绑定客户端版本，Agent 公共引用绑定连接地址摘要，均十分钟自动到期；补读不延长有效期，reference_seconds 表示签发时的期限。Redis 只保存引用摘要键、主体摘要、文档修订和字符位置、产品 / 版本 / 站点范围，不保存查询、标题或正文。补读从当前 SQL 发布修订读取原片段周围最多 4000 字符，不能任意指定文档或偏移，旧快照退役后仍能验证当前有效引用。更新授权或发布新修订后，旧引用需要重新搜索。

证据始终是不可信的参考数据；正文中的提示词、命令和“忽略指令”等内容不能获得工具权限。Agent 接入时必须仅作本轮临时证据，不原样写入长期记忆、学习库、复盘摘要或持久化工具轨迹；本接口的 ephemeral 提示本身不能替代宿主的留存控制。

JSON 请求体最多 8 KiB，不接受压缩体。Redis 共享固定窗口配额默认为每客户端每分钟 60 次、每连接地址每分钟 120 次；多 worker 共用，不缓存读取权限。Nginx 覆盖客户端自报的转发地址，部署若有上级反向代理，应仅对受信代理配置真实地址，不能信任任意 X-Forwarded-For。API 完整期限五秒；每进程最多四个真实 SQLite 查询线程，进度处理器限制约 2.5 秒，取消请求不会提前释放仍运行的线程容量。

Cloudflare 代理部署还需将 `docker/cloudflare-realip.conf` 安装为 `/etc/nginx/cloudflare-realip.conf`，并同步知识路由中的 include。该文件仅信任 Cloudflare 公布的回源网段，再用其覆盖写入的 `CF-Connecting-IP` 恢复访客地址；直连请求自报的同名头不能改变身份。否则引用会绑定到可能变化的 CDN 回源地址，使同一用户的补读偶发返回 410，多个用户也会共享配额。维护者应随代理网络变化核对官方网段；使用其他反向代理时应按实际受信来源配置地址恢复。

## 批准发布与独立索引

发布请求必须同时包含 expected_version 和明确的 revision。追加草稿不会自动发布，也不会改变原有发布版；发布前应查看目标修订。来源、集合及所属站点均须启用，才能批准发布。publish 响应的 index_pending 表示仍需构建；job.status 为 queued 不能当作已可检索。后台 status 的 generation 表示当前知识事实代次，active_generation 表示已激活快照代次，has_snapshot 只描述 SQL 是否存在快照指针，不代替文件可用性检查。

withdraw 请求包含 expected_version。撤回会在同一事务清除 SQL 发布指针并排队重建。原文历史保留，不能通过回退旧快照恢复读取权限；检索必须重新核对当前 SQL 指针和授权。集合、站点或来源的启停同样会请求重建；重新启用只带回仍被批准发布的修订。

索引任务持久化在数据库中，相同活动索引请求合并。构建期间有新的发布、撤回或开关变化时，完成者不会激活过时代次，而是补排下一任务。任务列表区分 queued、running、succeeded、failed、cancelled；outcome 为 activated 才表示此次完成了切换，superseded 表示构建期间事实改变，后继任务仍需执行。

worker 不在 Uvicorn 生命周期中运行。配置一个仓库之外的专用持久化数据卷，目录仅属主可访问，给 API 与 worker 挂载同一卷和 SQL 数据库，并在两个进程中显式设置：

    KNOWLEDGE_ENABLED=true
    KNOWLEDGE_DATA_DIR=/config/knowledge

独立运行：

    python -m app.services.knowledge.worker

本地或运维单次执行：

    python -m app.services.knowledge.worker --once

同一 Server 镜像可以通过覆盖 command 运行 worker，默认 Web 启动命令保持不变。首次必须运行包含知识表的数据库结构初始化；worker 自己也会调用现有结构初始化。私有目录不能位于源码、Git 仓库或共享临时目录中；现有目录权限过宽会明确报错，不会自动改动已有共享目录权限。索引为 0400 不可变 SQLite FTS5 文件，目录为 0700。FTS5 不可用会返回固定错误码并受控重试，不会替换为全库扫描或伪成功。

执行器使用 60 秒租约、约 20 秒心跳和单次 10 分钟构建期限；失败最多尝试三次，按 15、30 秒退避。旧租约不能续命或切换索引。等待中的任务可立即取消，运行中的取消由心跳及激活前检查确认；进程强制终止后由租约到期恢复。SIGTERM 停止继续认领并等待当前有界构建。worker 日志、任务错误和审计只记录标识、计数与白名单错误码；数据库引擎即使开启 DEBUG 也隐藏绑定参数。

若激活事务失去提交回执，可能已经提交，因此执行器保留完整快照，再按数据库事实恢复，不能因为网络异常删除已上线文件。索引内部格式为 2，仅属于中心私有实现，不是公共协议版本。

worker 每轮在 SQL 当前指针锁内回收中心管理的旧快照：始终保留当前指针及最近两份完成文件，其他完成文件需超过十秒宽限期，且没有有效运行中的索引租约才可删除。构建中遗留文件需超过二十分钟才清理，未知命名文件和符号链接不操作；SQL 不可用时不删除。已打开的不可变文件可继续读，打开前遇到切换会重新读取当前指针一次；引用补读依赖当前 SQL 而非旧文件。没有 worker 运行时不承诺到点清理。

可选 PostgreSQL 合同测试通过 KNOWLEDGE_TEST_DATABASE_URL 显式指定本机 knowledge_test 专用数据库。每个案例使用随机 schema 并在结束后删除，拒绝使用其他数据库名；未提供配置时明确跳过，不把方言编译当作数据库集成测试。

### 对明确批准的来源执行自动审阅

采集默认只生成待审修订。维护者可以在中心私有卷保存批准清单，再通过运维命令审阅这些来源的后续更新。该命令默认只预览，显式传入 `--apply` 才会调用正式发布服务、记录审计并排队索引：

    python -m app.services.knowledge.review --config /config/knowledge/ops/approved-sources.json
    python -m app.services.knowledge.review --config /config/knowledge/ops/approved-sources.json --apply

配置文件及其目录须仅属主可访问，文件不得为符号链接；清单和知识正文、Cookie 一样保留在中心私有卷，不提交到仓库或镜像。顶层 `sources` 数组每项包含来源 `id`、`binding`、`policy`、可选 `allowed_flags`。`binding` 通过 `app.services.knowledge.network.policy.binding(source)` 对所审阅的当前来源计算；`policy` 是该来源采集窗口返回的明确版本策略。批准前须核对集合、站点、目标 URL / 仓库、路径和正文选择器，不能只凭来源名称选择。

不指定 `allowed_flags` 时，任何采集警告都留待审；仅支持明确允许 `content_instruction`，其正文仍是不执行的参考数据。疑似秘密不能通过清单放行。来源身份或策略变化后，旧批准失效；同范围 Cookie 轮换则需要新的真实采集回执确认正文。只批准真实采集任务写入的当前待审 head，不批准手工或导入修订、已撤回内容、受保护候选、已取消或失败的任务。

命令检查空白或过短正文、登录 / 错误页、个人统计、异常大幅替换，并重新核对来源、集合、站点和在线开关。已发布版本保留至新修订通过审阅；检查仅为有限启发式规则，不判断所有语义错误。每轮默认最多检查 1000 篇，`--limit` 范围为 1–10000；输出只有计数和固定结果码，不包含正文、凭据或上游异常。

需要定期维护时，可由中心系统任务每 15 分钟调用，并使用 `flock` 排除重叠运行。命令使用部署的 SQL 配置，不需要保存后台密码或会话。索引仍由独立知识 worker 构建。

## JSONL 预检与明确导入

先建立 connector 为 jsonl 的来源，明确集合、产品与可选站点。上传使用原始 application/x-ndjson 正文，query 参数为 source_id 和当前 source_version，仍需 Cookie 和 X-CSRF-Token。不能上传 ZIP 或其他压缩体，不能指定文件系统路径。Nginx 专用入口最大 64 MiB，关闭请求缓冲并保留认证头；API 在认证后累计检查实际字节，不依赖 Content-Length。

单文件最多 64 MiB，单行最多 1 MiB，最多 50000 行。暂存准入为 512 MiB、最多四个未完成批次；不足时应完成或丢弃旧批次。上传期限五分钟，成功后暂存有效期 24 小时。独立 worker 或后续上传操作会清理到期批次；没有执行器运行时不承诺到点立即删除。有效运行租约持有的文件不会被到期清理误删。导入任务串行处理以控制暂存与事务资源，索引任务仍可由其他 worker 运行。

建议每行至少提供 external_id、title、content，可选 source_url 及明确版本元数据。external_id 是来源内稳定身份。inline-bot 式记录可使用以下预检配置；同一 source_id 可能对应多个文本块，直接拿它作为唯一身份会形成可见重复，不能默默覆盖：

    {
      "expected_version": 2,
      "expected_source_version": 1,
      "identity_fields": ["source_id", "title"],
      "title_field": "title",
      "content_field": "content",
      "url_field": "url",
      "origin_field": "source_id",
      "origin_values": ["explicit-source-to-import"],
      "metadata_mode": "fixed",
      "metadata": {"version_scope": "unknown"}
    }

字段只按顶层键读取，不执行脚本或 JSONPath。复合身份生成稳定摘要；标题等身份字段变化会成为新身份，因此应结合真实导出结构选择长期稳定字段。origin_values 只筛选外部记录，不决定中心权限；中心归属由后台来源绑定决定。筛掉的记录有明确计数与回执。若来源混杂，应分组选择到合适集合，不能把整包猜成同一产品。

metadata 必须明确 version_scope 为 unknown、all 或 range。fixed 模式不接受记录与明确范围矛盾；record 模式保留记录自带的标准元数据，并用批次值补充缺失项。产品、站点和中心归属仍不得越过后台绑定。未知时间保留 null。出处可保留 HTTPS 章节或行号片段，但不能携带认证参数；实际抓取地址仍禁止片段。

预检是独立 import 任务，返回 202 只表示排队。完成后查看 rows 列表与单行详情；列表不含正文，单行可对照所审阅基础修订与候选。重复身份、无效数据或疑似秘密形成阻止行；疑似秘密仅是启发式检查，不保证发现所有秘密，维护者仍应审阅。内容指令作为不执行的数据标记警告。被阻止行不回显候选正文。

apply 请求包含当前 expected_version、acknowledge_warnings，以及可选 skip_lines、append_lines。阻止行必须明确跳过或修正文件，人工修改冲突需逐行选择追加或跳过，重复 / 矛盾的决定会拒绝；不会静默跳过坏数据。每种行选择最多 1000 条，大范围问题应修正或拆分文件。

执行时再次核对计划摘要、来源版本与所审阅文档版本。所选写入、无正文行回执和任务终态在同一 30 秒有界事务提交；故障回滚，重试不会重复追加。状态为 review，原发布指针保持原样。已导入批次的原文件和计划随后清理，行回执仍能关联实际修订及旧版差异。人工保护以实际写入回执判断，不因为一次 unchanged 确认就把人工修订变成可自动覆盖的内容。

取消、丢弃、过期和提交回执丢失分别有明确状态；已经提交的导入不会因之后取消而撤销。若状态或计划过时，重新读取并预检，不要重复提交旧确认。附件不会自动导入，正式知识仍需单独审核和发布。

## 来源与正文

集合区分 mp、pt 领域，可自定义集合标识和显示名称，产品分支应使用独立集合。站点域名、名称和别名统一做歧义检查；同一规范化称呼不能指向两个站点。

来源类型包括手工文本、JSONL 导入、GitHub、HTTP 文档和 NexusPHP。只有手工来源可以通过文档接口直接新增草稿；网络来源由独立执行器生成待审修订，保存配置期间不执行抓取。

来源字段不能填写 Cookie、密码或认证 URL。普通来源接口不接受秘密字段，验证错误也不会回显误填的请求输入。采集凭据使用下面的独立维护入口，不能塞进 URL、路径或选择器。

正文保留 Markdown 空白，修改只追加新修订。新修订默认是 draft，不会自动发布，也不会改变已有发布指针。列表与操作审计不包含正文。

适用版本必须明确选择 unknown、all 或 range；范围边界使用稳定版本号。未知采集时间保持 null，中心录入时间不能代替真实采集时间。知识服务不可用或尚未发布时，调用方不能把这种状态解释为规则不存在。

## 采集凭据与部署密钥

每个网络来源独占一份认证密文，不支持任意跨来源引用秘密。普通管理员只能 GET 配置状态；PUT 替换以及 POST clear / rewrap 要求超级管理员、当前会话和 CSRF。网页来源支持 cookie 或 bearer；GitHub 仅支持 api.github.com 的 Bearer。手工和 JSONL 来源不接收出站秘密。

部署给 API 和未来采集 worker 设置同一个 KNOWLEDGE_KEY_FILE，指向仓库和镜像上下文之外的绝对文件，例如 /config/secrets/knowledge.json。文件须由运行用户持有且只有属主可读，建议 0600 或 0400，最大 16 KiB，不接受符号链接、FIFO、共享临时目录或 Git 仓库内文件。不要把真实密钥写进 Compose、源码、发行包、日志或本说明的示例中。

文件结构为 {"active":"key-2026","keys":{"key-2026":"独立生成的32字节密钥的URL安全Base64编码"}}；编码为 44 个字符，带末尾填充等号。最多保留八个命名密钥，标识限字母、数字、下划线和连字符，最长 32 字符。每次维护 / 解密都会读取当前文件，不使用长期进程缓存。缺失、权限错误、损坏或缺少指定旧密钥时固定拒绝，不自动生成默认密钥。请独立备份密钥环并限制访问；仅备份数据库不能恢复秘密。

先 GET /sources/{id}/credential。返回 configured、state、source_version、version、kind、host；没有配置时凭据 version 为 0。configured 只说明存在密文，不代表上游账号有效；state 为 unavailable 表示当前部署密钥或范围不能用于取用。任何响应都不含秘密、密文或 nonce。在线功能关闭时仍可预先配置，保存本身不发送网络请求。

PUT 请求为 {"expected_source_version":1,"expected_credential_version":0,"kind":"cookie","secret":"在受保护连接中填写认证值"}。secret 只填写值，Cookie 需含名称和值，Bearer 不带 Bearer 前缀；不接受控制字符、星号占位、完整请求头或隐式截断 / 去除空白。请求错误不回显输入。

密文使用 AES-256-GCM 和每次随机 nonce，认证附加数据绑定来源、目标摘要、秘密类型和凭据版本。目标摘要包括集合、站点、连接器、URL、仓库、分支、路径和选择器。已绑定秘密时这些字段都不能修改，须由超级管理员先明确清除凭据，再修改目标并重新配置；普通名称、启停及刷新周期可维护。

clear 和 rewrap 仅提交 expected_source_version、expected_credential_version；每次实际秘密变动都会递增来源版本和相应凭据版本，冲突返回 409。clear 删除当前密文；已经进入备份的旧密文仍需按备份策略管理。rewrap 保留认证值并用 active 密钥和新 nonce 重新加密，不把明文交给浏览器。

轮换时先将新密钥加入文件并设为 active，同时保留旧密钥；对各来源执行 rewrap，核对成功后才能移除不再使用的旧密钥。配置错误或缺失旧密钥时不覆盖原密文；成功响应丢失应先回读版本再操作。写入和不含秘密的审计在同一 SQL 事务中完成。

## 采集传输边界

采集任务通过下述维护 API 接入独立 worker，管理界面另行接入；保存来源和凭据均不会直接抓站。仅支持 GET、HTTPS 标准端口及明确来源。网页只读取后台配置的精确页面，GitHub 只访问指定仓库的文档相关 API；不会自动接受任意站内链接或跨主机下载地址。

每次请求和重定向重新校验范围，自定义解析器检查整组 A / AAAA 结果并将已验证地址直接交给连接器，socket 创建时再检查目标地址。拒绝私网、本地、链路本地、组播与映射 / NAT64 / 6to4 / Teredo 等过渡地址。保留原始主机用于 Host、SNI 和证书校验；没有可供表单关闭 TLS 校验的选项。

不使用环境代理、netrc、响应 Cookie 或自动重定向。最多三次跳转，跳转仍须为批准页面和主机。每次 fetch 最多十五秒，连接和读取另有更短期限，每进程最多两个 fetch，禁止隐式无限重试。响应最多 2 MiB，仅接收明确文档 / JSON 类型和 identity 编码，压缩响应明确拒绝，不进行自动解压。保留原始字节与声明字符集供后续解析器处理；304 单独交给任务层判断。

认证材料必须匹配当前来源与范围摘要；网络异常只给固定代码，不回显 URL、响应正文或认证头。429 的 Retry-After 数字或日期转换为最多一天的等待秒数，异常值使用一分钟；同配置手动重复触发会合并等待任务，不绕过限流退避。

## 网络采集、周期更新与待审差异

POST /sources/{id}/collect 提交 {"expected_version":当前来源版本}。仅已启用网络来源及其集合 / 站点可触发；202 表示 queued，并非采集成功。同来源同配置的活动请求合并；来源或凭据改变会请求取消旧任务并创建新任务，旧租约不得覆盖新配置。在线开关关闭时可预先排队，但执行器不会运行。

GET /sources/{id}/collection 返回 source_version、policy、next_at、最近 job 和 result。PUT 提交 expected_version、version_scope、min_version、max_version，保存明确的产品适用范围；range 要求集合已指定产品。范围不从 GitHub 分支或 commit 猜测，默认 unknown。策略变动递增来源版本，过时任务不提交。

refresh_minutes 为零表示仅手动。非零时由独立 worker 每轮在 SQL 锁内观察到期来源；首次观察或来源版本改变，先等待完整间隔，不在保存瞬间出网。到期与手动请求竞争只保留一个同配置任务。一个有效全局 collect 租约限制采集负载，导入和索引仍可由其他 worker 运行；受限种类在候选截断前过滤，不阻塞可执行索引。

GitHub 先将 branch 解析成完整 commit，再按该 commit 的 Git tree / blob 读取明确路径。真实文件 mode 用于排除符号链接和子模块，不依赖会隐式解析链接的 Contents 响应；不采用上游给出的 download_url。支持明确文本文件或有限目录，最多一百个文本文件、四十个目录、每目录少于一千项，遍历项最多一千；截断和超范围明确失败，不静默取前若干。blob 大小及对象散列均需匹配。非文本文件形成 excluded 回执。

HTTP / Wiki / NexusPHP 只读取来源 URL 及 paths 明确列出的相对页面，最多 101 页，不自动跟随站内链接。HTML 优先使用 selector；未指定时使用固定正文模板，找不到正文则失败。移除脚本、表单、导航、媒体和不安全链接后转为 Markdown；支持声明的字符集，未知编码不能静默变成乱码。普通网页连接器不猜测任意 JSON API 的正文结构。

NexusPHP 还会排除经典布局的 nav_block、info_block、userinfo、user_info、userinfobar 账号 / 导航容器，避免把当前账号和个人统计混入规则；article / main 内的 header 作为正文保留章节标题。拆除 mainouter 布局表的直属行列，保留内部规则数据表，避免整篇正文挤入一个 Markdown 单元格。站点定制布局应明确配置 selector，并在发布前检查提取结果；固定模板不能替代人工审核。

部署端 DNS 须返回真实公网地址；Fake-IP 或私网解析会被地址校验拒绝，不因其来自系统解析而放行。Cookie 原值不接受首尾空白；迁移既有配置时应检查复制内容，不能用完整请求头或星号占位值替代。

每批总期限两分钟，原始及归一正文分别最多 8 MiB，每篇不超过 262144 字符；写入事务另有三十秒期限。网络期间不持有 SQL 写锁。读取结束后重新核对当前租约、取消、来源 / 凭据版本与集合 / 站点开关，失效时不落正文。

成功页只追加 review 修订，不改原发布指针；未变正文不重复追加。普通 GitHub commit 更新但文件正文 / 范围未变时，也不重复产生修订，原修订保留首次观察的真实 commit / 采集时间。新任务回执记录本次 commit。首版按内容散列增量写入，网页仍取完整正文；未持有本地 HTTP 缓存基准时，304 不能当作成功。

登录、挑战、验证码页、空正文、疑似秘密或认证值反射被阻止；现有自动 head 大于四百字符、候选不足其四成时，严重缩水也被阻止。启发式检查不能保证发现全部秘密，管理员仍须审阅。内容指令只形成警告，不执行。

GET /jobs/{id}/collection 分页返回实际逐页回执：new、updated、unchanged、protected、failed、excluded，含固定 flags、实际文档 / 修订 / 候选引用及计数，不含原文或失败响应。部分可用页面与失败页面同时存在时为 collected_partial；全部页面暂时失败按有限次数退避，永久阻止为 collect_blocked。不可将这些结果统一显示成成功。

人工或采集中途修改的 head 不自动覆盖。安全可用的上游差异单独保存在中心私有候选中，回执给出 candidate_id；相同来源 / 文档版本和差异复用候选。GET 候选可对照当前人工正文和 proposal，维护者也可使用现有手工修订接口自行合并。

append 请求包含 expected_version（候选）、expected_document_version 以及 acknowledge_warnings；有内容警告时必须明确确认。只在候选、来源和文档版本仍匹配时追加待审修订，保留旧人工历史与发布指针。明确接受后，新 head 视为接受的上游版本，后续自动更新仍只追加待审；之后再次人工修改会恢复保护。discard 仅提交候选 expected_version，标记忽略而不改原文；上游或人工版本改变可生成新候选。

不可变修订、候选、无正文回执和任务终态同一事务提交。失败回滚；提交回执丢失后按 SQL 任务状态恢复，不重复追加。unchanged 回执不会把人工内容提升为可自动覆盖的内容。网络采集、待审维护与最终批准发布始终是独立动作。
